# Corley's Island: notes for Claude

- Start with the README: "How it fits together" (scripts, units, ground, saves) and "Working on it" (running, headless checks, the release steps). Before touching the ground, roads, trees or the editor, read `docs/map-editor.md`.
- Pushes to `main` deploy to Vercel (project `backhoe-dig`, Corley team). The claude.ai artifact (https://claude.ai/artifact/6nxYC5EK3422JouxaZx2DF) is the same game. Keep both in step: publish the artifact from `main` only, as the page from `<title>` to before `</html>` of `index.html`, with `css/game.css`, every `js/*.js`, `data/effort.js` (the game shows its version from it) and every jpg under `textures/` (the material library and the ground pack in `textures/ground/`) passed in `files` at the same paths (`shots/` is already there).
- Code layout (README has the table): markup in `index.html`, styles in `css/game.css`, game code in `js/*.js`. The scripts are classic scripts sharing one global scope and load in the order of the script tags; top-level code may only call functions from its own file or earlier files. Before adding a top-level name, grep `(const|let|function) NAME\b` across `js/` (and avoid browser globals like `top`, `name`, `status`).
- One session at a time merges to `main` and publishes the artifact; other sessions push branches and open PRs. Pick the version number when the work merges (next after `main`'s last `versions` entry), not when it starts, and fetch `main` again right before merging: another session can take that number in the meantime (merge its entry in and take the next one).
- Owner preferences for this game: flat-shaded low-poly look, imperial units in everything shown, large readable HUD text, runs above 30 FPS on his phone.
- Mud, puddles and other ground effects: the phone (Low graphics) may draw less than the PC, but what the ground does (ruts, water, mud) is the same on every device, since saves sync between them. Put any drawing cost behind the Graphics setting (`GFX` in gfx.js), never the behaviour.
- When a version ships, add an entry to `versions` in `data/effort.js` (asked/live times in Central, estimated developer hours, triangles and file size from `NODE_PATH=$(npm root -g) node tools/scene-check.js`) and add its hours to that day in `days` (`dh`, and `act` as half-hour blocks holding a release). The master dashboard (`corley-master-dashboard`, `LIVE`) and `build.html` both read it.
- Dev hours are a feature-by-feature judgment of one experienced three.js developer working by hand.
- `versions/` holds a playable snapshot of every version (https://corleys-island.vercel.app/versions/). After a version merges to `main`, run `python3 tools/versions.py` and commit `versions/` with it. Cloud clones are shallow, and the script then drops the snapshots whose commits it can't see: run `git fetch --unshallow origin` first, and check the commit deletes nothing outside the new snapshot. v1 to v6 were rebuilt by replaying the original chat's steps (the replay reproduced the saved v7 byte for byte); the script never touches them. Don't hand-edit other snapshots.
- Land a release on `main` as a merge commit whose first parent is `main` (a PR merge or `git merge --no-ff`), not a fast-forward of a branch: `tools/versions.py` walks `main`'s first-parent history to find each version's commit.
- If an artifact publish is refused because another session published since, read the files it names, check they match `main` before your merge (so nothing of theirs is lost), then publish again. Never force it.
- `baseHeight` (terrain.js) is the one source of the undug ground, and the map editor changes it at run time. Anything new built from the ground must read it live or be rebuilt in `edRefresh` (editor.js), as the mud tiles are (`mudEdRefresh`, mud.js).
- How wet the ground is (soak) is the soil water of rain.js, from rain and from painted Mud (which starts soaked when painted and dries out like other soil, through drier looks in materials.js); dug ground and ruts remember how wet they got (`soakMax`) and dry pale and cracked: `soakK`/`mudOf` (water.js) in the dig grid and `soakAt` (mud.js) elsewhere. Mud behaviour should read those, not the paint or the rain directly. Machines, assets and roads also have editor tools; keep them working when changing those systems.
- World units are metres (x east, z south, 0 = the mesa top); convert to feet for anything shown (`FT` in blocks.js).
- Headless Chromium (Playwright with SwiftShader) renders a frame in a second or more. Test behaviour by calling the game's functions from `page.evaluate`, and give screenshots a long timeout.
- Keyboard: every key goes through `js/keys.js`. A new key action is an entry in `KEY_ACTIONS` (group, name, what it does in each mode, default keys, and `s:'walk'` or `s:'ride'` if it only works on foot or in a machine, which lets it share a key with the other kind) plus a handler in `KEY_RUN` in `controls.js`; hold actions are read with `held(id)`. Don't test `e.code` directly (the map editor's own fixed keys are the exception). Tips and captions name keys with `keyLabel(id)`, so they follow the player's own keys.
- A machine the worker can climb into needs an entry in `WK_RIDES` and `rideOf` (`walker.js`) and in the inside list in `save.js`; anything that rides on the ground or lands on it should use `surfAt()` so blocks count.
- Idea board: https://claude.ai/artifact/FMrDEa4VsKvPS5Z3ktTrS3 (source `docs/idea-board.html`, ids and scores in `docs/IDEAS.md`). Picks sent from it arrive as a message listing ids; when an idea ships, mark it in the board's `DONE` and republish.
- The Family Island pavilion's chess and checkers tables open the separate Mesa site (repo mesa-games) with `?from=island&back=<url>` and come back via its "Corley's Island" link (`famPlay`/`famGameNear` in family.js, `bhd_table` in save.js; README "Pavilion games"). Keep `MESA_URL`, those parameter names and the return path working; a change on one side needs the other checked (Mesa's `NOTES.md` has its half). Moving the pavilion means moving `FAM_GAMES` with it.
