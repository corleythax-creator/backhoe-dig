HUD cleanup plan

What the screen is made of today, what's wrong with it, and an eight-step plan to make it cleaner and easier to understand. Each step ships on its own.

62key actions, run through 3 separate input paths (4 with VR)
~25HUD parts, each shown or hidden by its own file
11panels, each with its own open, close and Esc code
189toast calls, one message slot, no queue
15font sizes and 13 corner radii in the HUD CSS

How it works today

Layout

#hud is a 3×3 grid (css/game.css:20). Only four parts sit in the grid: the top bar, the right column (minimap and block bar), the sticks and the bottom bar. Everything else floats, placed by hand-picked offsets: top:22%, +64px, +72px, +84px, +124px, top:70px. Three size variables (--s, --ms, --cs) plus CSS zoom make UI size scale each part by a different amount.

How things happen

Keys go through KEY_ACTIONS → KEY_RUN (good). On-screen buttons each have their own click handler that calls the game function directly, the gamepad has a hard-coded button list (padButton), and VR has a fourth. Each contextual button (Get in, Hook box, Coupler, Grip, Pump, Wipers, Load, Bump, Reload) decides for itself when to appear, in seven different files. setMode handles only a few parts. Everything else checks the mode on its own every frame or every 0.1 s.

What's wrong

Broken now

  • Bug
    Tapping the pistol card to switch guns does nothing: #gunHud never turns pointer events back on (game.css:138).
  • Bug
    On foot, T fires both Carry and Block-or-thing: two walking actions share the key, and the clash check only runs when you rebind a key, never on the default keys.
  • Bug
    The gun stars, crosshair and pistol card sit inside .sticks, so they draw under the top bar and minimap. On the phone the pistol card is half behind the minimap.
  • Bug
    The heatmap key and the update button sit in the same place (top:22%). The lock hint and the wallet both sit at +64 px, and on phones the lawn chip moves there too. The wallet draws over an open menu.
  • Bug
    Esc doesn't close the menu, the Drive list or Sync. Ten other panels each listen for Esc on their own.
  • Bug
    If the top bar is docked at the bottom in the screen editor, the menu still drops downward, off the screen.

Confusing for the player

  • Words
    Drive means four things: the machine list button, a hidden mode button, the excavator's Drive/Dig switch, and the drive mode. Controls means two (the menu panel and the start card's box).
  • Machines
    The Drive list offers only 5 machines and hands you their sticks without seating you. The dozer, loader, semi, backhoe, pickup, carts, bike and boats are only reachable by walking up and tapping Get in. Tab and LB/RB cycle the same 6 modes, including the hidden one.
  • Reach
    Contextual buttons (Pump, Hook box, Coupler, Grip, Wipers) appear top right, far from your thumbs, among buttons that never change. Get in is bottom left, Load is in the walking row, Talk is a separate chip. There are four different places to look for "what can I do here".
  • Info
    The job gauges (bucket load, trench progress, truck load, lawn) are hidden. The bucket and lawn chips that replaced them are switched off with !important. You get no feedback on your work, yet the code still writes them all every 0.1 s.
  • Clutter
    The fps and triangle counter is always on screen. The menu mixes playing, the time and weather sliders, the AI talk model with its per-line costs, and seven developer tests in one long scroll.
  • Touch
    On a phone you can't reach the outriggers, Talk, Look ahead or Next machine. The touch walking row grows to 9 buttons in one line.
  • Messages
    One toast slot: a new message wipes the last one. About 20 messages bypass WORDS as raw strings, so the screen editor can't reword them.
  • Help
    How to play is a single wall of about 30 long entries. The Controls panel repeats much of it, and the gamepad text is typed by hand, so it has drifted from the code (LB/RB "previous/next machine").

Messy under the hood

  • CSS
    About 55 hard-coded colours (the gun, shop and wallet block hardly uses the tokens), 15 font sizes and 13 radii. 34 [hidden] rules duplicate the global one. --bar, --pb and #hud.lg are defined but nothing uses them.
  • Breakpoints
    The CSS splits at 640, 440 and 1000 px, the screen editor at 900/520, and the touch check is done in JS. A phone can be "phone" to one and "big" to the other.
  • Inputs
    Buttons repeat key logic instead of sharing it (Stats, Pump, Wipers, Blocks, Help). The C key works by clicking the camera button. Sprint is held on a keyboard but latched on touch. The heatmap has two different cycles.
  • Panels
    No shared panel manager: no back stack, gamepad B only closes help and the map, and each panel has its own backdrop and Esc code.

The target layout

Six fixed zones, each a stack that grows away from its corner, so things queue up instead of colliding. Each zone is a named grid-template-area, the same names the screen editor docks by. A part goes into a zone, never at an offset.

Status☰ · what you're in (Excavator, Dig) · wallet · clock and weather icon
NoticesOne stack, newest on top, at most 2: tips, warnings, lock hint, update, lawn progress
MapMinimap · compass · camera (Chase/Cab/Orbit) · Machines
Job cardPer machine: bucket, load, trench %, speed, ammo. Tap to fold
3D view, nothing else on it but the aim dot
Left thumbBig Use button (Get in / Talk / Buy / Play chess / Load) · left stick · caption
Panel trayBlock bar or shop slides up here when open
Right thumbUp to 4 action buttons for this mode (Dig/Drive, Pump, Hook box, Jump…) and More · right stick

Both thumbs get everything they need; the top is for reading, the bottom for doing.

The plan

  1. Fix what's broken Done · v342

    • Let the pistol card take taps; give Carry its own default key and check the default keys for clashes in keys.js at load.
    • Move the gun overlays out of .sticks; separate the heat key from the update button and the wallet from the lock hint.
    • Esc and gamepad B close the menu, the Drive list and Sync.
    • Stop writing gauges nobody can see, until Phase 4 shows them again.

    Every button you can see works, and nothing covers anything else.

  2. One action pipeline Done · v343

    • Add act(id): keys, buttons, gamepad and VR all call it, and the button handlers that copy key logic go away.
    • Give each KEY_ACTIONS entry an optional btn (its button id), pad (its controller button) and can() (whether it can be done now).
    • The gamepad map becomes data, so the Controls panel is generated from it and can't drift (rebinding it can come later).

    A new action is one table row, and it works on every input.

  3. One context system Done · v344

    • Add a CTX list: id, label (a WORDS id), mode, priority, when(). One 0.1 s tick picks what's shown, replacing the separate show/hide checks in main.js, coupler.js, rain.js, trenchbox.js, pickup.js, trimmer.js, pistol.js and family.js.
    • Fold Get in, Talk, Buy, Play chess, Load and Pick up into one Use button (F, gamepad B), labelled with the best thing to do right now. pbCtx already works this way for the pickup.
    • The right thumb shows the top 4 actions for the mode. The rest go under More, which ends the 9-button walking row.

    There is one place to look for what you can do here, right under your thumbs.

  4. Zones and the job card Done · v345

    • Rebuild #hud with the six named zones above. Each floating part moves into its zone's stack: wallet to Status; lawn, bucket and townsfolk chips to the job card or Notices; gun stars to Notices; pistol card to the job card.
    • Bring back the gauges as one job card per machine (bucket, truck load, trench, mowing, skid load, ammo), with large readable numbers in feet, yd³ and mph. It folds with a tap.
    • One --ui scale variable for every part instead of three plus zoom.
    • Move fps and triangles into Graphics, with a "Show frame rate" switch (default off).

    Nothing overlaps at any size, and UI size scales the whole screen evenly.

  5. Machines, named once Done · v347

    • Rename the top button to Machines. It lists every machine, including the dozer, loader, semi, backhoe, pickup, carts, bike and boats, with how far away each is. Picking one seats you in it, the same as walking up and tapping Use.
    • The excavator and backhoe switch becomes Tracks / Arm (backhoe: Wheel / Hoe), so "Drive" means only driving. Delete the hidden #modeDrive.
    • Tab and LB/RB cycle the nearest machines, not a fixed list of 6.

    Every machine is one tap away, under one name.

  6. Menu and panels Done · v348

    • One panel manager (panel.open(id)) with a back stack. Esc and gamepad B close the top panel, and every card shares one backdrop.
    • The menu gets tabs: Play (map, stats, how to play), Build (map editor, every item, edit the screen), World (time, date, weather), Settings (graphics, sound, controls and keys merged, screen size, minimap, sticks, messages, townsfolk talk), Developer (the seven tests, speed test, reset, frame rate).

    The menu fits on a phone screen without scrolling, and the developer tests are out of the player's way.

  7. Messages and help Done · v349

    • The toast becomes a queue in the Notices zone: priority, merging of repeats, at most 2 shown. Convert the raw-string toasts to say() ids so the screen editor can reword them.
    • Replace How to play's wall of text: a short card the first time you get into each machine (from WORDS), and a searchable list of topics in Play.

    Help shows up when you need it, and you can turn it off.

  8. Tokens, CSS cleanup, screen editor Done · v350

    • A type scale of 4 HUD sizes (14 / 17 / 22 / 30 px), 3 radii and colour tokens for gun, shop and wallet. Drop the duplicate [hidden] rules and the unused variables.
    • One breakpoint pair shared by the CSS and the screen editor (phone ≤ 900 wide or ≤ 520 tall).
    • The screen editor docks by zone names. Update GUI_PEEK, GUI_GROUPS and guiDockCss, run tools/gui_editor.py and republish the screen editor.

    The owner can move any zone in the screen editor, with no code.

Total: about 56 developer hours, released as 8 versions in order. Phases 1 and 2 can go out right away. Phases 3 and 4 are the big visible change.
